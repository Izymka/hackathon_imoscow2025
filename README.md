# 🏥 ИИ сервис для выявления компьютерных томографий органов грудной клетки без патологий 

> *«Точность начинается с данных»*

## 1. Краткое описание решения и его назначения
ML‑сервис принимает на вход архив (ZIP) с DICOM‑исследованием КТ грудной клетки, автоматически парсит и подготавливает объём к анализу, выполняет инференс модели (классификация «норма/патология») и возвращает результат через HTTP API, а также сохраняет отчёт в XLSX в смонтированную директорию.

Назначение: автоматическая первичная triage‑оценка КТ грудной клетки для выделения исследований без признаков патологии.


## 2. Основные возможности и ограничения системы
Возможности:
- Принимает ZIP‑архив с DICOM‑исследованием (серия файлов или многофреймовый DICOM) через HTTP API.
- Проводит предобработку:
  - Извлечение архива, поиск корня DICOM‑серии.
  - Приведение к изотропному воксельному размеру 1×1×1 мм, нормализация HU, кадрирование.
  - Преобразование к стандартизированному тензору для 3D‑модели.
- Выполняет инференс обученной модели и возвращает:
  - Метку класса (0 — норма, 1 — патология).
  - Вероятности по классам и уверенность (confidence) для предсказанного класса.
  - Диагностическую сводку по DICOM (UIDы, размеры, параметры сканирования и т.д.).
- Сохраняет XLSX‑отчёт в смонтированную директорию, путь отдаётся в ответе API.
- Предоставляет эндпоинты FastAPI:
  - POST /process — основной эндпоинт обработки.
  - GET  /healthcheck — проверка готовности сервиса.

Ограничения:
- Поддерживается модальность CT; исследования других модальностей не предназначены для обработки данным сервисом.
- Ожидается один исследовательский ZIP на запрос; пакетная обработка выполняется последовательной серией запросов или за счёт увеличения числа воркеров.
- Точность и выводы модели зависят от качества входных данных (DICOM метаданные, толщина среза, артефакты и т.п.).
- Большие архивы могут требовать значительного времени и памяти на распаковку и предобработку.
- В контейнере по умолчанию используется CPU‑инференс; поддержка GPU не включена (см. Dockerfile и requirements).


## 3. Системные требования
Минимальные:
- ОС с поддержкой Docker (Linux/Windows/macOS).
- Docker 20.10+.
- CPU: 2–4 vCPU.
- RAM: от 4 ГБ (рекомендуется 8 ГБ и более для больших исследований).
- Свободное место на диске: от 5 ГБ (для образа, распаковки и временных файлов).
- Открытый локальный порт для публикации сервиса (по умолчанию 8010 на хосте).

Опционально:
- Для ускорения можно увеличить число воркеров uvicorn через переменную окружения WORKERS (по умолчанию 1).

Решение просто демонстрирует возможности работы сервиса. Для полноценного теста нужно использовать локальное тестирование

### Локальное тестирование

1) Подготовьте директорию для данных, которая будет смонтирована в контейнер:
- На хосте создайте папку ml-storage и поместите в неё ZIP‑архив с DICOM‑исследованием.

2) Запустите контейнер (порт 8010 на хосте будет проксировать 8000 внутри контейнера):

```
docker run --rm -p 8010:8000 -v ./ml-storage:/mnt/storage --name ct-ml-docker ghcr.io/izymka/hackathon_imoscow2025:latest
```

Если на вашей машине доступны GPU, используйте следующую команду с параметром `--gpus all`:

```
docker run --rm --gpus all -p 8010:8000 -v ./ml-storage:/mnt/storage --name ct-ml-docker ghcr.io/izymka/hackathon_imoscow2025:latest
```


3) Отправьте запрос на обработку (замените {{DICOM_PATH}} на имя вашего ZIP‑файла в смонтированной директории):

```
curl --location 'http://localhost:8010/process' \
--header 'Accept: application/json' \
--header 'Content-Type: application/json' \
--data '{
    "zip_path": "/mnt/storage/{{DICOM_PATH}}"
```

### Параметры визуализации (опционально)
Сервис может сохранять PNG‑визуализацию объяснимости предсказания рядом с XLSX‑отчётом.

- SAVE_EXPLANATION_IMAGE: true/false — включает сохранение PNG визуализации исследования.
- SAVE_IMAGE_FOR_NORMA: true/false — если включено, PNG создаётся и для случаев, предсказанных как «норма» (по умолчанию true). Если выключено — PNG сохраняется только для «патология».

Как задать параметры при запуске контейнера:

```
# CPU‑вариант
docker run --rm -p 8010:8000 \
  -e SAVE_EXPLANATION_IMAGE=true \
  -e SAVE_IMAGE_FOR_NORMA=true \
  -v ./ml-storage:/mnt/storage \
  --name ct-ml-docker ghcr.io/izymka/hackathon_imoscow2025:latest

# GPU‑вариант (при наличии GPU)
docker run --rm --gpus all -p 8010:8000 \
  -e SAVE_EXPLANATION_IMAGE=true \
  -e SAVE_IMAGE_FOR_NORMA=true \
  -v ./ml-storage:/mnt/storage \
  --name ct-ml-docker ghcr.io/izymka/hackathon_imoscow2025:latest
```

Где искать PNG:
- Файл визуализации с расширением `.png` будет сохранён в той же смонтированной директории рядом с результатами исследования (`.xlsx`).

## 🔄 Подготовка DICOM для подачи в модель

Преобразуем разрозненные DICOM-файлы в стандартизированные 3D-тензоры фиксированного размера.

### 🌟 Ключевые особенности

| Этап | Описание |
|------|--------|
| **📏 Изотропное ресемплирование** | Все объёмы → **1×1×1 мм** (устраняет анизотропию, критично для 3D-CNN) |
| **📦 Стандартный формат** | Тензор: `[1, 1, 256, 256, 256]` (`[batch, channel, D, H, W]`) |
| **✂️ Обрезка ROI** | Автоматическое удаление фона (воздуха) вокруг тела пациента |
| **📊 Нормализация HU** | Диапазон `[-1000, 600]` → масштабирован в `[-1, 1]` |
| **🔄 Универсальная загрузка** | Поддержка: <br> • Серий DICOM (много файлов)<br> • Многофреймовых DICOM (один файл) |

---

## ⚙️ 3. Алгоритм обработки (пошагово)

1. **📥 Загрузка DICOM**  
   - Определение типа (серия / многофрейм)  
   - Применение `RescaleSlope` / `RescaleIntercept` → корректные HU  
   - Извлечение метаданных

2. **📐 Ресемплинг**  
   - SimpleITK → изотропное разрешение **1×1×1 мм** (линейная интерполяция)

3. **✂️ Кроп по ROI**  
   - Порог: `HU > -1000`  
   - Margin = 5 вокселей

4. **⚖️ Нормализация**  
   - Clip: `[-1000, 600]` → Scale: `[-1, 1]`

5. **📏 Фиксированный размер**  
   - Трилинейная интерполяция → `[256, 256, 256]`  
   - Конвертация в `torch.Tensor` → `[1, 1, 256, 256, 256]`

6. **💾 Сохранение**  
   - Формат: `.pt` (PyTorch)  
   - Логирование метаинформации

## 🤖 Модель

> **3D ResNet-34**, дообученная на медицинских данных с использованием предобученных весов **MedicalNet**  
> *(MedicalNet: предобучение на 23 медицинских датасетах)*


**Model Architecture**

- **Input**: `256³`  
- **Initial Layer**:  
  - Convolution: `7×7`, stride 2, padding 3  
  - Batch Normalization (BN)  
  - ReLU activation  
  - Max Pooling: `3×3`, stride 2, padding 1  

- **Residual Blocks**:  
  - **Layer 1**: 3 blocks, 64 channels  
  - **Layer 2**: 4 blocks, 128 channels  
  - **Layer 3**: 6 blocks, 256 channels  
  - **Layer 4**: 3 blocks, 512 channels  

- **Final Layers**:  
  - Global Average Pooling  
  - Adaptive Fully Connected (FC) Layer  
  - **Output**: 2 classes (binary classification)

## 🚀 План развития

> **Приоритет**: Сбор данных, где «норма» = истинно здоровые пациенты (не просто «не-COVID»).
